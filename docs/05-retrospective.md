# 05 - 复盘（Retrospective）

## 最难的三个问题

**1. 冲突查证放在哪一层，"不凭空选一个答案"才不是台词？**
最初考虑让 `search_docs` 直接返回 `has_conflict` 标记，但这意味着"冲突认定"是工具层的预设逻辑——模型只是转发，恰恰落入"固定条件分支不视为 ReAct"的否定项，也经不起审核要点"替换文档内容，核对答案与动作是否改变"的检验。最终让工具只返回文档事实：模型逐一读取原文后，从各自相关句提取"数值+单位"陈述（30 天 vs 15 天）自行认定冲突，连带"两份文档均未说明适用范围与优先级"也是检查原文用词得出的——D02 如果改写成"差旅费报销期限 15 天"，冲突说明会随之变化。代价是 Mock 策略要做句级提取，收益是查证过程全程可审计。

**2. 引用怎么保证"支持回答"且不是摘要冒充的？**
审核要点把"错误引用"列为关键缺陷。数据流上做了结构隔离：检索返回的 `snippet` 只参与排序与"读哪篇"的决策，**作答与引用只允许使用 `read_doc` 返回的原文**，相关句按句切分提取后逐字进入 citations，测试对每条引用断言 `quote ∈ 文档 content`。这样"引用支持回答"不靠模型自觉，靠数据通道保证。

**3. 追问场景的检索词怎么改写，才不会把上文"串味"？**
省略式追问"那事假呢？"需要结合上文（上一轮问的是年假）才能理解。最初的改写方案把上文主题词并进检索词（"事假 年假"），结果同时命中 D03（年假 5 天）与 D04（事假 3 天），两篇不同数值被误判为"文档冲突"——其实是两个不同问题的答案。修正：追问改写只取**本轮**核心词（"事假"），上文的用途是让模型理解"省略掉的主语是什么"（写入决策依据供审计），而不是扩检索面。这个 bug 让"结合上文改写"的粒度从"扩面"收敛到"消歧"，也更贴近真实对话系统的做法。

## 学习收获

- **事实与判断分离是问答可靠性的根基**：工具给文档事实，冲突认定、依据是否充分、要不要追问都留在模型侧——既是 ReAct 真实性的来源，也让"无依据回答"在结构上被堵住（回答文本只能由原文片段组装）。
- **评测先行于实现**：先把 6 个验收点 + 红线写成可执行断言；"内容替换鲁棒性"测试（test_8）直接来自审核要点，它倒逼实现从第一天起就不允许硬编码任何答案。
- **检索改进是决策不是实现**：改写检索词、补充检索、读哪篇原文，这些选择属于模型；工具的检索质量（2-gram 打分）只是地板。Trace 里每步的 `decision_basis` 让"为什么这样检索"可复盘。

## 下一步（按优先级）

1. **接入真实模型验证**：用 `AGENT_MODEL=api` 跑通同一组验收用例，对比 Mock 与真实模型的 Trace 差异；为 API 模式增加输出 JSON 校验与格式漂移重试。
2. **语义检索**：把 2-gram 打分换成 embedding 召回（本地小模型即可），检验"改写后的相似问题"在真实语义检索下的行为差异。
3. **冲突消解回流**：用户确认适用制度后，把确认结果写回知识库元数据（如标注适用范围），让同类问题下次可以直接作答——形成 HITL 闭环。
4. **pass^k 稳定性**：同一用例重复运行 k 次验证真实模型下的稳定性（对 Mock 无意义，对 API 模式必要）。
5. **引用粒度细化**：citations 支持句级定位（句子序号/字符偏移），方便前端高亮原文。
